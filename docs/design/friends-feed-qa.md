# 首页跑友动态方案 3 验收（2026-09-30）

## 范围与视觉目标

- 设计来源：本轮 Product Design 的第 3 张方案图，结构为一条重点跑步记录和两条简洁记录。
- 实现页面：`pages/index/index` 的「跑友动态」、`pages/mydata/mydata` 的「常用服务」。
- 设计图中的昵称、公里数与凭证图是示意；运行页面使用 `acty/getsports` 返回的真实记录。

## 本轮核验

| 项目 | 结果 |
| --- | --- |
| 首页服务入口 | WXML 中已移除常用服务区；首页动态直接接在跑步热力图后。 |
| 我的服务入口 | 已登录页显示「常用服务」标题、打卡记录、我的兑换、兑换好礼；管理入口沿用管理员角色控制。 |
| 跑友动态 | 微信开发者工具 iPhone 17 模拟器完整编译后显示三条真实记录；重点记录的大号公里数、头像、日期、配速和凭证图可见，下方两条用分隔线组织。 |
| 凭证交互 | 点击重点记录后，原生图片预览显示完整原图。 |
| 数据状态 | 首次加载、接口失败、无记录分别有文字反馈；不填充设计稿示意数据。 |
| 静态检查 | `node --check` 检查首页与我的 JS 通过；六个本轮修改文件的 `git diff --check` 通过。 |

## 差异与限制

- 设计图的示意凭证是跑步风景图；实际上传凭证可能是地图截图、其他图片，页面按原图显示。
- 设计图上方露出的是挑战区；当前首页按照已定页面结构，动态位于跑步热力图之后。
- 模拟器截图在本轮工具输出中人工核对，未另存为项目文件；真机尺寸和弱网场景未核验。
- 开发者工具显示项目级调试提示；本轮确认动态数据渲染与图片预览可用，未把整个项目的调试提示计为本功能的通过项。
