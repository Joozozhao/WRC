# 首页本月跑量与打卡融合

## 需求与视觉方案

将首页「本周跑量」改为「本月跑量」。保留当前暖白、深松绿、荧光绿的设计语言，以现有首页代码和已选首页参考图为基础，只重设计这一块。

- 整合为一张白色月度卡片：标题/月份及查看详情 → 大号本月公里数/目标与完成百分比 → 细进度条/目标来源 → 本月打卡天数、连续打卡、累计跑量 → 星期和逐日日历。
- 移除「本月日历」标题，月度标题统领数据与日历，日历前仅保留细分隔线和适度留白。
- 卡片圆角24rpx，左右内边距约28rpx；首页原来的44rpx外边距保留。大数字约72rpx，辅助文字20–24rpx，进度条12rpx左右。
- 已打卡日期继续显示当日公里数和绿色色阶，未打卡日期显示日期；未来日期弱化。沿用现有真实资产，不增加装饰图。
- 「查看详情」进入我的页；当前挑战与跑友动态保留原有入口。

## 数据口径

- 使用 `user/getMonthList` 的本月日跑量同时生成本月累计、唯一打卡天数及逐日日历，排除其他月份、未来日期和无效/负数跑量；同日只计一天。移除首页周汇总及用周数据补充月日历的请求，避免口径混用。
- 目标来自本月已报名的普通月度挑战，以详情 `has_clickon=1` 和正数个人 `target` 为依据；不能用最低报名公里数 `distance` 替代个人目标。
- 不采用下月、历史月、全年或V挑战目标。多个本月已报名挑战时按最新活动编号确定一个；确认没有后用77公里，不累加多个挑战。
- 挑战列表有分页，检查完整列表后才确认没有报名。详情失败、分页失败或报名目标无效不能假称未报名，展示待确认并支持重试。
- 本月跑量接口、目标接口的加载/失败/游客状态分别处理，未加载的统计为「—」而非零，刷新和切用户不能接受旧响应。
- 进度百分比可超过100%，进度条宽度限制0–100%；零跑量是有效值，目标必须是正数。

## 验收

1. 已报名本月个人目标，未报名默认77；其他月份、全年/V挑战不影响本月目标；当前月候选在后续页也能发现。
2. 月累计与逐日数据一致、同日计一天；月底、跨年、闰月和未来日期；0、超额与异常值。
3. 两接口返回顺序、失败重试、重复刷新、切用户和游客状态。
4. 模拟器查看真实数据卡片融合、无「本周跑量/本月日历」残留、长目标与大数不溢出；详情与挑战导航可用。
