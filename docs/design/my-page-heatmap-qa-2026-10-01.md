# 我的页面与近三个月热力图

## 用户要求
重新设计 `pages/mydata/mydata`。本月跑量卡片下方紧接 GitHub 式热力图，色块仅表示跑量强弱，不显示日期、星期或具体公里数。

## 设计与数据范围
- 延续 WRC 暖白、松绿及黄绿色强调色。顶部缩为「我的跑步」与跑者资料；月跑量使用深绿主卡，热力图使用白底独立卡。
- 信息顺序：个人资料 → 本月跑量及周/年/累计汇总 → 最近三个月 → 积分与小花儿 → 双列常用服务 → 马拉松与参与记录。
- 热力图每周一列，每列固定七个方格；从左到右为较早到较近的周，范围外首尾格透明。仅保留「少／多」色阶说明，无日期、公里数、点击气泡。
- 「最近三个月」采用截至当天的滚动三个日历月。起点为当天减三个月（不存在同日则取月末）加一天，终点为当天。2026-10-01 对应 2026-07-02 至 2026-10-01。
- 五级颜色：未跑、0–3、3–7、7–12、12 公里以上。界面不展示这些数值。
- 保留个人资料、积分、小花儿、打卡记录、兑换、管理、马拉松与参与记录入口。

## 接口核实
2026-10-01 对模拟器已登录用户进行了只读接口核实：
- `user/getMonthList` 返回月对象，但当前仅有本月、上月，不能以缺少历史月份认定更早日期没有跑量。
- `user/getsportlist` 提供 `sport_date`、`distance`、`state`、唯一 `id`，以及 `page_total`、`total`、`page_size`。热力图需完整分页读取，再按运动日期聚合。同一记录 ID 去重；已驳回不计入，待审核与已通过延续现有跑量口径。
- 返回记录并非严格按运动日期倒序，不能在遇到一条旧运动日期时提前停止。服务端当前固定每页 15 条（请求 `page_size=100` 仍返回 15 条）。
- 真实数据不会写入测试文件或本记录；隔离测试使用构造数据，不执行上传、打卡、修改或删除。

## 数据与验证边界
历史记录采用最多四个请求并发的完整分页读取，记录越多加载成本越高。任一页失败、结构畸形或分页总数发生变化即显示重试，完成时去重记录数必须与服务端总数完全一致；异常超过 1000 页报错以防无限请求。后端将来提供日期范围聚合接口后可减少读取量。
