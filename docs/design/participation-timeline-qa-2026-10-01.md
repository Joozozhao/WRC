# 「我的」参与记录 · 方案 2 实现与验收

用户选择三稿中的 B「时间列表」，授权开始实现并可指派 Kimi。Kimi k3-256k 完成参与记录组件，主代理完成数据合并、父页接入、分页保护与验证。

## 实际布局

- 沿用暖白底、深松绿文字和荧光黄绿选中线，取消挑战/团跑的大外框及横滑卡片。
- 分类为「全部 / 挑战 N / 团跑 N」，复用已加载记录；切换分类从 8 条开始展示，不重新请求接口。
- 已加载的两类记录按接口活动开始日期倒序，分组到月份；月份标题下使用细时间线与圆点，名称、日期在左，150rpx 缩略图在右。
- 日期缩短为 `YYYY.MM.DD`，保留真实年月日，不推断完成状态。无效/缺失日期置于末尾并明确说明，标题最多两行，封面缺失或加载失败显示占位。
- 仍使用原有挑战详情与团跑详情入口；空态可进入对应分类发现活动。

## 数据与分页

继续使用现有 `acty/getacty` 接口，分别请求「挑战」「团跑」。总数只有接口确认后才显示；缺失/失败显示 `—`，成功的零记录显示 `0`。

首次展示 8 条，本地有更多时每次展开 8 条；本地展开完再读取相应源的下一页。请求期间阻止重复加载，成功后才推进页码。失败保留原记录与待重试页，部分源失败不会清空另一源。刷新、切换用户、注销和页面销毁会作废旧回调，避免旧用户结果回写。

源内以 id 合并重叠记录，源间相同 id 保持独立。分页响应为空但总数仍有未读取记录、只有重复记录或响应结构错误时提示重试，不冒充已全部加载。页脚只写「已显示 N 条记录」。日期排序针对已加载记录，下一页合并后重新排序。
